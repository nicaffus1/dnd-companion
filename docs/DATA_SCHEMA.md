# Phase 2 data schema
IndexedDB database dnd-companion, database version 1, store state, key root. A single validated snapshot makes campaign/character selection and backup restore atomic. schemaVersion 1, revision (monotonic), campaigns [{id,name,ruleset,createdAt}], characters [{id,campaignId,name,createdAt}], activeCampaignId, activeCharacterId. IDs are stable UUIDs; ruleset immutable per campaign. Future versions must explicitly migrate the snapshot before adding gameplay records. Writes use expected revision to prevent stale overwrites. Restore validates the complete v1 envelope, previews counts, requires explicit replacement approval and commits in one transaction. Backups are plain JSON; keep them private and download regularly. No cloud sync. Future records: classes, features, resources, items, spells, rolls, chapters, sessions, codex, relationships, packs, transactions and settings.
